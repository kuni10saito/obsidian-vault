# 第13章　推論デプロイと評価・改善ループ　要約

## 全体像
模倣学習は学習して終わりではなく、以下のループを繰り返すことで実用性能に到達する：
**デプロイ → 評価（成功率測定） → 失敗分析 → データ追加 → 再学習 →（先頭へ）**

## 13.2 学習済みモデルのデプロイ
- `lerobot.record` に `--policy.path` でチェックポイントを指定し自律実行
- 評価時はリーダーアーム不要（ロボットが自律動作）
- Colab学習時はHugging Face Hub経由でモデルをMacに移す

## 13.3 成功率の測定
- 10〜20エピソードを実行し、映像を人手で確認して成功/失敗を記録
- HIL-SERLの報酬分類器で自動判定も可能（精度に依存、人手確認推奨）
- 目安：初期マイルストーン50〜60%、実用レベル80〜90%
- 信頼性のため最低10、できれば20〜30エピソードで評価

## 13.4 失敗の分析
よくある失敗パターンと対策：
- **掴めない** → 該当位置のデモ追加
- **掴んで落とす** → 把持〜持ち上げのデモ強化
- **震え・カクつく** → Temporal Ensemble調整、学習増
- **途中停止** → chunk_sizeを10〜15に増やす
- **特定の見た目だけ失敗** → 該当バリエーションを重点収集

→ 失敗は「モデルの欠陥」ではなく「見たことのない状況」が原因である場合が多い

## 13.5 データ追加と再学習
- 失敗箇所を特定したら、そのバリエーションを重点的に10〜20エピソード追加
- 1周ごとに潰す失敗を1〜2種類に絞ると改善効果が見えやすい

## 13.6 デプロイ時の注意点
- **環境の一致**：照明・カメラ位置・背景・対象物を収集時と揃える
- **安全確保**：緊急停止をすぐ行える体制で見守る
- **推論負荷**：解像度・カメラ台数・chunk_sizeを調整してリアルタイム性を確保

## まとめ
- 模倣学習は「デプロイ→評価→失敗分析→データ追加→再学習」の反復で向上
- 成功/失敗はまず人手で正確に記録する
- 失敗は多くの場合データ不足が原因→該当状況を重点的に補う
- 評価環境は収集環境と揃えることが重要
