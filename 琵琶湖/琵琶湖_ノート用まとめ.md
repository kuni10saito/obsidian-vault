## 1. まず、琵琶湖を3Dにした

### 湖底と陸を1枚の標高場に繋ぐ

湖底だけを描くと、湖が宙に浮いて見える。
**国土地理院のDEMタイル（z=13）で周囲の陸地を取り、湖の部分は
「湖面標高 84.4m − 水深」に差し替えて、1枚の連続した標高場にした。**
境界は湖岸線のマスクで切り替わるので、湖岸で段差なく繋がる。

|     |                                           |
| --- | ----------------------------------------- |
| 範囲  | 東西 63.9 km × 南北 79.9 km                   |
| 標高  | −20 〜 1376 m                              |
| 推奨版 | `biwa_terrain_mid.usdc` — 524万頂点 / 114 MB |

湖面は不透明度 0.55 の**別メッシュ**として持たせた。
4隅すべてが湖内にある四角形だけを面にしているので、湖の外まで
水面が広がることがない。

> 国土地理院タイルを使ったものには「国土地理院タイルを加工して作成」の
> 表示が要る。これは義務。

### 湖の中だけ、深さを10倍にする

ここが効いた。

**琵琶湖の最深部は104m。まわりの山は1376m。同じ鉛直誇張をかけると、
湖底は平板にしか見えない。** 湖の窪みが読めない図に意味はない。

そこで陸と湖で誇張倍率を分けた。

|      湖内の倍率 |     湖底のz | 見え方               |
| ---------: | -------: | ----------------- |
|    3（陸と同じ） |      −59 | 平板                |
| **10（採用）** | **−788** | **窪みが読める。自然**     |
|         30 |    −2869 | 盆地は明確だが、湖だけ浮いて見える |

水深0の湖岸では倍率によらず同じ高さになるので、陸との接続は崩れない。

> ただしこれは**表示専用の歪み**である。陸と湖で鉛直スケールが違うので、
> **この図から傾斜・体積・断面を読んではいけない。**

### ブラウザで、ダブルクリックで回る

USDはブラウザで開けないので glTF に変換した。

**`biwa_terrain_3d_offline.html`（28.8 MB）をダブルクリックすれば、
ブラウザで琵琶湖が回る。** ビューア本体もモデルも全部埋め込んだ単一ファイルで、
**外部参照ゼロ＝オフラインで動く。** 配るのはこれ1個でいい。

Draco圧縮で **338 MB → 26.4 MB（12.8倍）** まで落ちた。

#### 踏んだ罠を3つ

1. **glTFはkm単位で出すこと。** model-viewer や three.js は、
   数万単位の大きさのモデルを**黙って読まない**。エラーも出ず、ただ真っ黒になる。
   1.7 KB の立方体でもサイズ80000にすると落ちた。頂点数ではなく**スケール**の問題。
   USDはm、glTFはkm。
2. **遅延読み込みを切ること。** 既定では読み込みが始まらない環境がある。
3. **半透明は専用の設定が要る。** 不透明度の値を入れるだけでは
   不透明で書き出され、湖底が見えなくなる。

#### 直した不具合：南湖の南端が切れていた

DEMの取得範囲の南限が湖岸線より内側にあり、**湖セルの3.19%が欠落**していた。
湖面メッシュの南端は、湖岸線ではなく**DEM格子の縁**を描いていた。

> **教訓：湖の端が直線に見えたら、湖岸線ではなく格子の縁を疑う。**

## 2. 「流れを出さない」まま、流体として動かす

このモデルは1次元の鉛直カラムで、**流れ（速度場）を解いていない。**
対流はパラメータ化されている。だから**速度ベクトルを出せば嘘になる。**
矢印も流線も出さない、と決めている。

それでも「水が動いている」絵は出せた。**拡散のラグランジュ表現**を使う。

モデルが解いているのは

```
dT/dt = d/dz ( K(z,t) dT/dz )
```

で、これと等価なのが、局所のKに応じたランダムウォークで動く粒子群である。
**粒子の動きはモデルが解いている式そのもの**なので、飾りではない。
水平には動かさない。動くのは深さだけ。

粒子の深度分布が水の体積分布と一致するかを全フレームで検証し、
**±0.006 以内**で合っている。

### 滞留日数 —— 粒子でしか出せない量

粒子には履歴を持たせられる。**「最後に表層に触れてからの日数」**である。

貧酸素化とは要するに「深層水が何日ぶんの酸素消費を溜め込んだか」なので、
酸素の絵と並べると **貧酸素な水 ＝ 長く表層に触れていない水** として
境界がぴたりと一致する。これは一目で伝わる。

| 日付             | 酸素 [mg/L]          | 滞留日数     |
| -------------- | ------------------ | -------- |
| 03/01（起点）      | 11.99 一様           | 0        |
| 12/01          | 2.46〜10.22         | 〜275日    |
| **03/01（1年後）** | **11.95〜12.02 一様** | **〜32日** |

1年かけて溜めた275日ぶんの澱みが、深呼吸で32日に若返る。

### 出来たもの

- `biwa_annual_temperature.mp4` / `_DO.mp4` / `_age.mp4` — 通年の3本
- `biwa_fail_DO.mp4` / `_age.mp4` — **循環しなかった場合**
- `biwa_overturn_quad2.mp4` — 成功例と失敗例を**地図×2・断面×2の4画面で並べたもの**

失敗例は最初、色分けが読めなかった。水温で塗ると成功も失敗も似た色になる。
**滞留日数で塗り直したら、失敗した年は深層に「古い水」が残り続けるのが
はっきり出た。** 見せたい量で塗る、というだけの話だが、これに気づくまで
「断面図なら差が出るはず」という筋の悪い仮説を試して外している。

## 3. PhysicsNeMo —— 使って、主役から降ろした

この研究はもともと **NVIDIA Modulus（現 PhysicsNeMo）の PINN**
＝物理法則を損失関数に組み込んだニューラルネットで湖を解く、という構想で始まった。
そこが一番語るべきところだと思うので、正直に書く。

> **PhysicsNeMo は Modulus の改名**（2025年、NeMoファミリーに統合）。
> 別物ではなく後継。`import modulus` → `import physicsnemo`。

### やったこと：Sym移行は完了している

PINN本体を **PhysicsNeMo-Sym** 版に書き換えた。

- 手書きの自動微分**14回連鎖** → `NavierStokes` + `AdvectionDiffusion` ×2 の
  **宣言的な定義**に置換
- 手生成の境界点 → `PointwiseBoundaryConstraint`
- 観測データの同化 → `PointwiseConstraint.from_numpy`
- **新規にホールドアウト検証を追加**（浅い層で学習し、深い層で評価）

DGX Spark（GB10）で動かすため、**PhysicsNeMo-Sym の Docker イメージを
新規に作った**（23.5 GB）。ホストへの直接インストールは
CUDAバージョンのミスマッチで通らない。

- **GB10 では JIT を切るのが必須**（融合カーネルがコンテナ側の
  コンパイラで通らず落ちる）
- 学習速度 約 50 ms/step
- 深度ホールドアウト（学習≤30m / 評価45〜60m）で **温度RMSE 0.657℃**、
  深いほど劣化する傾向も出た

**動くところまでは、ちゃんと持っていった。**

### わかったこと①：2D断面のPINNは原理的に行き詰まる

浮力を入れた2D版は破棄した。理由が2つあり、どちらも本質的である。

1. **静水圧平衡による相殺。** 浮力項と圧力項がどちらも 10⁴〜10⁷ の大きさで、
   実際の駆動力はその**差の O(1)**。PINNの損失は残差の二乗和なので、
   意味のある解を得るには**相対誤差 10⁻⁷** が必要になる。学習できない。
2. **アスペクト比。** 対流プルームの水平スケールは深さと同程度（〜100m）だが、
   断面の幅は 11,900m。プルームは領域幅の **1/119**。
   滑らかなMLPでは解像できない。

現業の湖沼モデルも対流は解像せずパラメータ化している。**同じ壁である。**

### わかったこと②：1次元の順問題では、PINNは古典手法に負けた

PINN解の妥当性を独立に確かめるため、**有限体積法のソルバ（numpyだけ、GPU不要、
ノートPCで数十秒）** を書いて突き合わせた。**重大な食い違いが出た。**

|              |      PINN |      有限体積法 |
| ------------ | --------: | ---------: |
| 15日の表層水温     |    10.48℃ | 10.48℃（一致） |
| 45日の混合層深度    |    57.5 m | **74.7 m** |
| **全層循環の到達日** | **86.2日** |  **55.0日** |

**表層の熱収支は一致しているのに、混合層の深まりがPINNでは大幅に遅い。**

原因は、混合層の底が**鋭い移動界面**（拡散係数が126倍から1倍へ切り替わる）
であることだった。**滑らかなMLPはこれを鈍らせる。** 取り込みを過小評価し、
到達日が31日ずれる。

> **残差の値だけを見ていては、これは判断できなかった。**
> 独立解と突き合わせて初めて分かった。

さらに、PINNの本来の売りである**逆問題**（観測から拡散係数を推定する）でも、
PINNの推定は真値の **1.47倍**。同じことを有限体積法＋パラメータ走査でやると
**0.67〜1.36倍**に収まる。**順問題解の誤差が、そのまま逆推定の偏りとして出た。**

### 結論：役割分担を書き換えた

```
有限体積法 → 順問題・真値生成・パラメータ掃引   ← 主役はこちら
PINN       → 逆問題・データ同化・サロゲート
Earth-2    → 将来予測の気象強制
```

**1次元カラムに関する限り、PINNを主役にする理由がない。**
論文ドラフトは「従来モデルは計算コストが高い」を差別化点にしていたが、
**1次元の順計算については、その主張は成り立たない。**

これは PhysicsNeMo が悪いという話ではない。**道具の選択の話**である。
PINNの優位性には別の根拠が要る —— **高次元のパラメータ場、異種データの同化、
順問題そのものが高価な3D。** つまり、**モデルを3Dに広げたときに戻ってくる。**

### 同じ判断を Omniverse Kit CAE でもした

可視化の最終形として想定していた Omniverse Kit CAE も、**保留にした。**

Spark（GB10）で Kit が実際に起動することは実測で確認した
（互換性チェックは「ARM CPUがサポート表に無い」ためFAILEDと出るが、
GPU・ドライバ・OSはいずれも supported で、起動完了まで到達する）。
**「動かない」のではなく「動くが割に合わない」。**

理由は単純で、**Kit CAEの看板機能である流線・ベクトル場が、
このモデルでは使えない**（速度場を出さない方針だから）。
残る価値はブラウザ配信だけだが、それには**サロゲートモデルが先に要る。**
計算に数分〜十数分かかるものを配信しても、再生と視点操作しかできず、
それは動画とほぼ同じである。

**順番は サロゲート → Kit CAE。** 逆にすると価値が出ない。
当面は ParaView の状態ファイルとデータ一式（17MB）を配れば、
学生が自分の端末で時刻も視点も量も操作できる。無料・全OS・GPU不要。

## 4. 物理として成立したこと

可視化の裏で、モデル自体はきちんと実測に合っている。

### 較正に使っていない量で検証が通った

拡散係数 K_bg は深層の水温から決めたが、
**混合層が季節を通してどう深まるか**は較正に使っていない。
それが**8月から1月まで全月で実測の範囲に入った。**

| 月   |    モデル | 実測の範囲     |
| --- | -----: | --------- |
| 8月  |  5.7 m | 5.7〜11.0  |
| 10月 | 10.9 m | 10.7〜19.1 |
| 12月 | 35.9 m | 22.0〜46.9 |
| 1月  | 68.2 m | 46.9〜89.0 |

**K_bg = 1e-5 でのみ成立する。3e-5 では11月・12月・1月とも外れる。**

### 風と気温の役割分担がはっきり分かれた

| 現象             | 決めているもの | 根拠                       |
| -------------- | ------- | ------------------------ |
| **深層の酸素の季節変化** | **風**   | 最小日の相関 r=+0.90、平均誤差7.6日  |
| **全層循環が起きる日**  | **気温**  | 風だけでは年々差 0.5日、気温を入れて4.8日 |

風の効き方が面白い。**深層の混合は、年間を通してじわじわ効くのではなく、
強風の日にまとめて起きる。** 実測で **上位10%の日が、年間の深部混合の50%**
を担っていた。

そこで拡散係数を風速の3乗で変調した。**時間平均が1になるように正規化**
してあるのが肝で、平均値は動かない。それでも深層の酸素回復量が
**+0.33 → +1.04 mg/L** に増えた（実測は+1.66）。
**改善したのは「平均を上げたから」ではなく、間欠性そのものの効果である。**

### 主結果 —— 臨界の温暖化量

気象庁 彦根の1991-2020平年（年平均15.0℃）からの偏差でみる。
観測期間の2018-2025は既に **+1.0℃**。

|      平年比 |      現在比 | 全層循環の発生確率 |
| -------: | -------: | --------: |
|     +1.0 |     ±0.0 |       97% |
| **+2.0** | **+1.0** |   **13%** |
|     +3.0 |     +2.0 |    **0%** |

**あと1℃で、湖が息をする年は半分以下になる。**

> **正直に書いておく限界。** 現在の発生確率97%は、実測の75%（8年中6年）より
> 楽観的である。実際の気温・風で8冬を回しても**8冬すべてで循環してしまい、
> 不成立の年が1年も出ない。** モデル自体が循環しやすすぎる。
> だからこの臨界値は「湖盆平均が循環しなくなる閾値」であって、
> 県の「一部水域で未確認」という判定よりは甘い。

## 5. その「循環しやすすぎる」の正体が、3D化の入口で見えた

ここが最新（2026-09-05）。

長いあいだ「1次元だから水平の不均一が作れない。だから不成立年が出ない」
と考えていた。**では3Dにすれば足りるのか。** それを確かめる一番安い方法として、
**水平の混合をゼロにした極限** —— 各地点を「その水深の独立した柱」として
別々に解く —— を計算した。これは**地形だけで作れる分散の上限**である。

|             水深 | 循環日       |  湖盆平均との差 |
| -------------: | --------- | -------: |
|           30 m | 11/23     |     −69日 |
|           60 m | 01/25     |      −6日 |
|           90 m | 02/21     |     +21日 |
| **104 m（最深部）** | **03/02** | **+30日** |

**地形だけで99日の分散があった。必要だったのは36〜57日。足りるどころか余る。**

### 判定の取り方が食い違っていた

そして、こちらの方が本質的だった。

**県の判定は「一部水域における未確認」＝空間の最小値**（最も遅い地点が
揃うかどうか）である。**一方こちらのモデルは、面積で重みをつけた平均を
解いていた。**

|             | 循環日                         |
| ----------- | --------------------------- |
| 現行モデル（湖盆平均） | 01/31                       |
| 最も遅い地点      | **03/02**                   |
| 実測の不成立年     | 02/25（2019年度）・03/22（2018年度） |

**同じ物理・同じパラメータのまま、判定の取り方を変えるだけで、
不成立年の時期が出る。**

「1次元では水平不均一を原理的に扱えない」と書いていたが、
**深度方向の不均一は、面積深度曲線 A(z) の中に最初から入っていた。**
それを平均で潰していただけだった。

### ただし、問題が解けたのではなく入れ替わった

最も遅い地点で判定すると、**全部の年が一律に+30日ずれる。**
成立年（実測 01/08〜02/02）まで 03/02 になってしまい、今度はそちらが合わない。

> 必要なのは**一律の遅れではなく、年による差**である。
> 成立年には最深部も揃い、不成立年には最深部だけが残る、という機構。

これが次の課題。**水平交換の強さ K_h を入れた多カラムモデル**を作る。
K_h を無限大にすれば現行の1次元に一致し、ゼロにすれば今回の独立カラムになる。
実測の「同じ深さの地点間の水温差（中層で平均0.43℃）」を再現する K_h を
求めるのが、較正の入口になる。

**そしてここで、PhysicsNeMo が戻ってくる余地がある。**
多カラム・3Dに広げれば順問題は一気に高価になり、パラメータ場も高次元になる。
**「1次元では主役にする理由がない」と書いた条件が、そこで変わる。**

## まとめ

- **琵琶湖を3Dにした。** 陸と湖底を1枚に繋ぎ、湖の中だけ深さを10倍にして、
  ブラウザでダブルクリックすれば回る単一HTMLにした
- **流れを解いていないので流れは出さない。** 代わりに拡散と等価な粒子で、
  「最後に空気に触れてから何日」を可視化した。貧酸素の水と、古い水の境界は一致した
- **PhysicsNeMo は移行まで完了させたうえで、1次元では主役から降ろした。**
  滑らかなニューラルネットは、混合層の鋭い界面を鈍らせる。
  独立解と突き合わせなければ気づけなかった。3Dに広げれば戻ってくる
- **物理は合っている。** 較正に使っていない量で検証が通り、
  風が酸素を、気温が循環日を決めることが分かれた
- **あと1℃で、湖が深呼吸する年は半分以下になる**
- **最後の壁だと思っていた「水平不均一」は、実は判定の取り方の問題だった。**
  地形だけで分散は足りている
