# トラックB：Isaac Lab（強化学習）

## Reach タスク：完了

sim-to-real を一周し、**実機の物理限界をシムのパラメータに翻訳する**サイクルを確立した。

| `effort_limit_sim` | シム位置誤差      | 実機で動く関節 | 判定             |
| ------------------ | ----------- | ------- | -------------- |
| 1.9（STS3215 ストール値） | 2.3cm       | 3/6     | 実機で再現できない架空の精度 |
| **0.6**            | 4.1cm       | **5/6** | ✅ **最適点**      |
| 0.4                | 16.5cm → 発散 | —       | ❌ PPO が学習不能    |

**`effort_limit` には「実行可能性の下限」がある。** 下げるほど実機に近づくわけではない。
0.6 はストールトルクの約1/3で、「連続トルクはストールの30〜50%」の経験則と整合する。

残る `wrist_flex` はトルク不足で、パラメータ調整では解決不能と結論済み。

## 💡 最大の洞察：「指令」ではなく「実現された状態」を送る

| 方式         | 実機に送る値            | 全6関節動くか   |
| ---------- | ----------------- | --------- |
| ONNX 単独推論  | ポリシーの**生の指令**     | ❌ 5/6     |
| **ミラーリング** | シム内で**実際に到達した位置** | ✅ **6/6** |

ONNX は「シム内でも到達していない目標値」を実機に送ってしまう。
ミラーリングはシムの物理エンジンが**実行可能性のフィルタ**として働く。

## Lift-Cube：シム学習は完了、実機は道半ば

実物と同じ4cmキューブで再学習（`scale 0.6667` / `minimal_height 0.030`）。

| 指標                     | 結果                               |
| ---------------------- | -------------------------------- |
| `lifting_object`       | **11.56 / 15（77%）** ✅ 掴んで持ち上げられる |
| `object_goal_tracking` | 1.71 / 16（11%）❌ 運搬は無理            |

キューブ重量は寸法の3乗＝2.37倍になった一方、腕のトルクは実機基準の0.6に制限している。
**「拾い上げる」までがこのハードの現実的な射程。**

## 物体検出とカメラ較正：完了

| 項目            | 結果                    |
| ------------- | --------------------- |
| 再現性（10回の標準偏差） | **X 0.0mm / Y 0.0mm** |
| 正確性（真値との差）    | 6〜9mm                 |

4点ホモグラフィの再投影誤差0.0mmは**精度の証明にならない**（8未知数を8式で解いているため定義上一致する）。
較正に使っていない第5点で検証して 9.1mm を得た。

# 🔑 2つのトラックが衝突している場所

これがこのまとめの要点。

```
Desktop/run_groot.py  ←── GR00T（模倣学習）のクライアント
  ├─ HOME_POSITION = {1:1505, 2:2242, 3:1400, 4:2375, 5:2438, 6:3100}
  └─ MOTOR_LIMITS  = {1:(1600,3050), 2:(2050,4095), 3:(100,2100),
                      4:(100,2350),  5:(100,3500),  6:(2000,3350)}
            │
            └──→ RL 側の so101_rl_deploy.py / so101_lift_deploy.py が
                  そのまま流用している
```

`MOTOR_LIMITS` は **GR00T の模倣学習データに現れた範囲**であって、機械的な可動域ではない。
人間がデモした軌道の外側を切り落とした値なので、**RLポリシーが要求する姿勢とは無関係**。

しかも既に自己矛盾している：

| 関節           | HOME | MOTOR_LIMITS | 矛盾                |
| ------------ | ---- | ------------ | ----------------- |
| shoulder_pan | 1505 | (1600, 3050) | **HOMEが下限を95下回る** |
| wrist_flex   | 2375 | (100, 2350)  | **HOMEが上限を25超える** |

**HOME 姿勢でいるだけでクランプが常時作動している。**

> ここが「トラックAの遺産がトラックBを縛っている」実例。
> `--limits {groot|stage1|sim}` で切替可能にはしたが、**正しい値の確定は未着手**。

### なぜ実測が難しいか（発見4）

重力負荷のかかる関節では、自動測定は「機械端」ではなく「**トルク限界**」を測ってしまう。
`wrist_flex` の測定値が20度しかなく、しかもHOME実測値(2362)より上限(2351)が低いという
矛盾が出た。**正しい機械端はトルクOFFで手で動かして記録するしかない。**
