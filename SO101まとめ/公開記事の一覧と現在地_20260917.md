## 記事①：Claude Codeで Isaac Sim（4）GR00Tでアームロボットを動かす

**2026-05-30 公開** ／ https://note.com/legit_poppy7873/n/n3c9de5caee18

### 要旨

SO-101（低価格オープンソースアーム）に、NVIDIA の基盤モデル **GR00T N1.6-3B** を
ファインチューニングして、**ブロックを掴んでカップへ入れる**タスクを自律実行させた記録。

| 項目 | 内容 |
|---|---|
| ロボット | SO-101（LeRobot準拠、STS3215モーター） |
| 学習 | GR00T N1.6-3B を 97エピソードで10,000ステップ |
| 実行環境 | DGX Spark（aarch64） |
| 結果 | **pick→place の自律動作が30Hzで安定** |

### つまずいた点

- Python 3.14 の互換性問題 → `scservo_sdk` を直接叩くスクリプトを自作
- USB変換器のCOMポート自動検出（VID:PID）
- ローカルPC→Spark の ZMQ 通信で実効15Hzに低下 → **ロボットを直結して解決**
- **カメラ位置が数cmずれると距離推定が大きく狂う** ← 後の伏線

### 結論

> ロボット学習はソフト・ハード・根気の総合格闘技

## 記事②：Claude Code で Omniverse 2-2　Physics NeMoを使って琵琶湖の全層循環停止問題を解く

**2026-09-10 公開** ／ https://note.com/legit_poppy7873/n/n69dc57a02104

### 要旨

琵琶湖の**全層循環**（冬季に湖全体が混ざる現象）が2019-2020年に停止した問題を、
**PINN（物理情報ニューラルネットワーク）**で3次元解析した研究。

| 項目 | 内容 |
|---|---|
| 手法 | Physics NeMo（旧 NVIDIA Modulus）＋ PINN |
| 可視化 | ParaView |
| 鍵となる物理 | **水の密度が3.98℃で最大**という非線形性 |

### 主な結果

- **1次元（湖盆平均）モデルは統計的に棄却される**
- 臨界温暖化量は従来推定の **+1.0℃ ではなく +0.4℃**
- 循環が **70〜100日**かけて進行する様子を3Dで可視化
- ただし**年ごとの予測は不可能**（検証データ n=8 で不足）

### 位置づけ

ロボティクスとは別テーマ。[[並行セッション関係図_20260911]] の
**琵琶湖クラスタ**（セッション `7c971d93` 他）の成果にあたる。

## いまやっていること：記事①の続き

記事①は**トラックA（模倣学習）**の成功記録。
現在は**トラックB（強化学習）**——同じロボット、同じタスクを、
**シミュレータで学習させて実機に載せる**方を進めている。

| | 記事①：トラックA | 現在：トラックB |
|---|---|---|
| 学習方法 | 人が操縦して覚えさせる | Isaac Lab のシム内で強化学習 |
| 座標変換 | **不要**（raw値→raw値） | **必要**（ここが難所） |
| 実機での把持 | ✅ **成功**（30Hz自律） | ❌ **まだ掴めない** |

### なぜ片方だけ動かないか

**翻訳層の有無。** 模倣学習はサーボの数値を見てサーボの数値を出すので、
シムの座標系を経由しない。強化学習はメートル・ラジアンとサーボカウントを
対応づける必要があり、そこに誤差が入る。

### 見つかった誤差源（6つ）

| # | 誤差源 | 大きさ | 状態 |
|---|---|---:|---|
| 1 | 基準値に `HOME_POSITION` を流用（M1〜M4） | 56 mm | ✅ |
| 2 | 回転方向の符号（M1・M4） | 反転 | ✅ |
| 3 | 爪の向き（M5 が90度ずれ） | — | ✅ |
| 4 | サーボの積分ゲインが全関節ゼロ | 20 mm | ✅ |
| 5 | 把持点の定義がモデルと30mm違う | 30 mm | ✅ |
| 6 | 握力不足（M6のトルク上限が他の半分） | — | ⬜ |

**記事①の「カメラ位置が数cmずれると狂う」と同じ構造**が、
今度はサーボの基準値で起きていた。

### 記事にするなら
