# Spark への移行と、機械をまたぐときの規則

2026-09-12 に DGX Spark で Obsidian を試験運用した記録。**FMV が本番、Spark は試験、切り替えは後日**という前提。

---

## 1. 前提が1つひっくり返った

`CLAUDE.md` には「FMV（実行端末）＝クライアントスクリプト／DGX Spark＝学習・推論」と書いてあった。**実測すると逆だった。**

```
Spark   /dev/ttyACM0  /dev/ttyACM1        ← SO-101 のアーム2本
        QinHeng USB Serial × 2
        Logitech C270 × 2                 ← 学習用カメラ
        Unifying Receiver / モニタ接続あり
Windows COM ポート **なし**
```

**実機・カメラ・GPU・モデル・データセットは全部 Spark にある。** SO-101 の作業は、ハードが刺さっている機械に対して SSH で往復していたことになる。

訂正版は `~/vault-so101/CLAUDE.md`（Spark）に置いた。`~/claude_context_fmv/CLAUDE.md` が FMV ミラーの正規の置き場らしいので、反映するかはトラックB の判断に委ねた。

> **ホーム直下に `CLAUDE.md` を置いてはいけない。** 配下の全プロジェクトに継承されるので、他セッションの文脈に勝手に入り込む。一度置いてしまい、`~/vault-so101/` へ退けた。

## 3. 踏んだ罠（全部ここに書く）

### pkill の角括弧は万能ではない

`CLAUDE.md` は「`pkill -f "[r]un_..."` の角括弧は必須」と書いているが、**正確には「その文字列がコマンド行のどこにも現れないこと」が条件**である。

```bash
#  自爆した例。角括弧を使っているのに SSH ごと切れた
ssh HOST 'x11vnc -storepasswd ...; pkill -f "[x]11vnc"; nohup x11vnc ...'
                  ^^^^^^                                       ^^^^^^
                  この2つにマッチして、自分のコマンド行を殺す
```

**起動処理をスクリプトに閉じ込めるか、文字列をその場で組み立てる。**

```bash
S=$(printf 'x11%s' 'vnc')
pkill -f "$S"
```

### nohup では足りない。setsid が要る

**前景では正常に動くのに、背景に回すと消える**という症状が出た。`nohup` は SIGHUP しか防がないので、SSH 経由でスクリプトから起動すると、親スクリプトの終了時にプロセスグループごと片付けられる。

```bash
setsid "$APP" < /dev/null > log 2>&1 &
disown
```

### AppImage のフォルダ選択ダイアログが開かない

「フォルダーをボールトとして開く」は OS のネイティブダイアログを呼ぶ。`xdg-desktop-portal` が無いと押せない。**`~/.config/obsidian/obsidian.json` に直接書けばダイアログを通らない。**

```json
{"vaults": {"<md5の先頭16桁>": {"path": "/home/saito/vault-xxx", "ts": <ms>, "open": true}}}
```

### コミュニティプラグインは初回に止まる

新しい環境で初めて開いた Vault では、`community-plugins.json` に名前が載っていても制限モードで動かない。**設定から手で解除する。**

### 画面が切れて右サイドバーが見えない

2560×1600 のまま VNC で繋ぐと、クライアントが縮小表示していなければ左上の一部しか見えない。**Claudian は右サイドバーにいる**ので、まさに見えない領域だった。`~/setres.sh 1680x1050` で解像度を落とす。

> 物理モニタも一緒に変わる。Spark の前に座るときは `~/setres.sh 2560x1600` で戻すこと。

### PowerShell の `bash` は WSL に解決される

```
PS> bash ~/Downloads/biwa_push.sh
wsl: C:\Users\saito\.wslconfig の無効なキー名: 4
/bin/bash: /home/saito/Downloads/biwa_push.sh: No such file or directory
```

**同じ `~` が別の場所を指す。**

| | `~` の実体 |
|---|---|
| Git Bash | `C:\Users\saito` |
| WSL | `/home/saito` |

仮にファイルが見つかっても、**中の `C:/Users/...` は WSL からは見えない**（WSL なら `/mnt/c/Users/...`）。中途半端に動くほうが危ないので、全スクリプトに `uname -s` のガードを入れた。

```bash
case "$(uname -s)" in
  MINGW*|MSYS*) : ;;
  *) echo "**Git Bash で実行すること**" >&2; exit 1 ;;
esac
```

PowerShell から直接呼ぶなら:

```powershell
& "C:\Program Files\Git\bin\bash.exe" "C:/Users/saito/Downloads/biwa_push.sh"
```

### Windows で日本語を出すスクリプトは PYTHONIOENCODING が要る

`cp932` は `—` `⇄` などを出せず `UnicodeEncodeError` で落ちる。

```bash
PYTHONIOENCODING=utf-8 python xxx.py
```

### ssh のヒアドキュメントに Windows パスを書いてはいけない

`C:\Users\...` の `\U` が Unicode エスケープと解釈されて Python が構文エラーになる。**スクリプトはファイルとして送る。** 2回踏んだ。

### Claudian が `Claude Code process exited with code 1` で落ちる

CLI 単体は正常だった（`claude -p` も `--output-format stream-json` も `--permission-mode bypassPermissions` も終了コード 0）。PATH・HOME・認証・`/usr/bin/claude` の発見、すべて問題なし。**Electron から起動したときだけ落ちる。**

`~/bin/claude` に診断シムを置き、PATH の先頭に入れて捕まえた。

```
① --model claude-haiku-4-5 ... --tools  --setting-sources=... --no-session-persistence
                                ^^^^^^^^ **値が空**。exit 行が記録されなかった
② --model opus --thinking adaptive --effort high ...   → exit: 0
```

**stderr は空だった。** だからエラーに中身が付かず「code 1」しか出ない。

①の空の `--tools` が原因の候補だが、**未確定**。そして**再起動したら動いた。再起動で直ったものは原因を特定したことにならない。**

再発したらシムを戻して観察する。

```bash
mkdir -p ~/bin && cp ~/claudeshim ~/bin/claude && chmod +x ~/bin/claude
bash ~/obs2.sh     # ~/bin/claude があるときだけ PATH に足す作り
```

記録: `~/claude_shim_20260912.log`

### kill してから起動し直すと Obsidian が上がらない

`obs2.sh`（kill しない）は必ず成功し、kill を挟むスクリプトは何度やっても失敗した。**マウントの残骸もゾンビプロセスも無いのに。原因未特定。**

`obs2.sh` を「起動だけ担当」に固定した。**落とすときは画面で閉じる。**

### リモート一覧が空のまま進むと全件上書きになる

双方向同期の初版で、リモート一覧を取る ssh の入れ子クォートが壊れて空を返した。

```
リモート一覧 = 空 → 「相手には何も無い」と判定 → 67件すべてを片方向に上書き
```

確認モードで走らせたので実害は無かった。**一覧が空なら異常終了する**ガードを入れた。

## 4. 機械をまたぐときの規則

**規則は1つだけ。**

> **いま、どちらが正か。決めてから触る。**

これを守れば壊れない。破ればどちらかの編集が消える。

### 琵琶湖（セッションごと引き渡す）

```bash
bash ~/Downloads/biwa_push.sh    # FMV → Spark。実行後、FMV では書かない
bash ~/Downloads/biwa_pull.sh    # Spark → FMV。実行後、Spark では書かない
```

Vault の中身とトランスクリプトの両方を運び、`cwd` フィールドを相手の形式に書き換える。`--full` を付けると `biwa/`（149 MB の図と動画）も運ぶ。

> **本文は書き換えない。** 会話中で言及されている Windows パスは履歴なのでそのまま残す。直すのは Claude Code が作業ディレクトリの判定に使う `cwd` のみ。

### SO-101（内容だけ同期する）

```bash
bash ~/Downloads/sync_so101.sh                              # 片方向 FMV → Spark
PYTHONIOENCODING=utf-8 python ~/Downloads/sync2_so101.py     # 双方向（確認のみ）
PYTHONIOENCODING=utf-8 python ~/Downloads/sync2_so101.py --apply
```

双方向は**前回同期時点の基準点**（`~/.so101_sync_state.json`）を持つ。これが無いと「相手が編集した」と「自分が古いだけ」を区別できない。

```
前回から片方だけ変わった  →  その向きへコピー
前回から両方変わった      →  **衝突。触らない。名前だけ出す**
片方にしか無い            →  新規としてコピー
```

**削除は同期しない。** 片方で消えたファイルを「削除された」と見るか「まだ来ていない」と見るかは基準点だけでは決められず、誤れば取り返しがつかない。

**同期しないもの:**

```
.obsidian/workspace.json        Obsidian が開いている間ずっと書き換わる
.obsidian/plugins/*/data.json   環境ごとに違って当然
```

両方で Obsidian を立ち上げたら、`workspace.json` は毎回必ず衝突する。**中身と環境設定を分けるのが前提。**

## 5. 判断として残っていること

| 項目 | 状態 |
|---|---|
| Electron の ARM での体感速度 | **未評価。**使ってみないと分からない |
| 切り替えの時期 | SO-101 の2セッションが区切りについてから |
| 琵琶湖が2箇所にある件 | 「琵琶湖は FMV で」の方針なら、試験後に Spark 側を消すのが筋 |
| `claude_context_fmv/CLAUDE.md` への訂正反映 | トラックB の判断 |

**移行の本当の利点は、実機・カメラ・GPU・データセットが全部 Spark にあること。** SSH の往復が丸ごと消える。Electron が多少遅くても、そちらのほうが大きいかもしれない。

逆に体感が致命的に悪ければ、**「Obsidian は FMV、Claude Code だけ Spark でローカル」**という折衷もありうる。
