## 5. この案件で繰り返し起きた失敗（AI側の注意）

| 失敗                  | 具体例                                                             |
| ------------------- | --------------------------------------------------------------- |
| **画像から位置関係を判断して外す** | 何度も外した。**実機の前にいる人の観察が常に正しかった**（「爪は上下」「30mm上空」）                  |
| **検証していない前提を使う**    | `SERVO_AT_DEFAULT = HOME_POSITION` は56mmずれていた。コードに「【仮定】」と書いてあった |
| **測る対象を間違える**       | 高さ8点で較正した気になったが、水平は56mmずれたまま                                    |
| **数字を見る前に結論を書く**    | 9/25、出力の結論行と同じ出力内の表が矛盾していた                                      |
| **無効なテストで結論を出す**    | 全関節を1500で初期化 → M6の安全範囲外で永久にクランプ                                 |
| **確かめていない前提で設計する**  | 9/28、シムの開閉指令をそのまま実機へ送る設計にした → dry-run で保持中も535回ばたつくと判明。対策も1回外した（シムが開ききる前に掴むことを見ていなかった） |
| **観察と数字を軽く扱う**       | 10/1、RL の「手前で爪が閉じた」を「成功」と報告した（M6 が 2146〜2154＝閉じ切りで空振りと、数字にも出ていた）。握れていたのに「掴めていなかった」と書いた |
| **出力の数字をノートに残さない** | 9/29 の運搬の「ずれ 28.8mm」を書かずに「成功」とだけ記録した。カメラの読み違いと分かるまで、2日見逃した |
| **検証していない前提で原因を絞る** | 10/2、「カメラは定規で較正したから正しい」と決めつけ、肩の遊びや土台の回転を先に疑った。定規でカメラを直接測ったら、原因はカメラだった |
| **安全のための判定をゆるめる**   | 10/2 の較正で、停止位置の「深すぎ」を「置き方では変わらない」と判断して通した → その点だけ 1cm ずれていた |
| **位置関係を推測で案内する**     | 10/2、「爪の真下が作業範囲の真ん中」と案内したが、実際は 3.5cm 手前だった（計算で確かめていなかった） |
